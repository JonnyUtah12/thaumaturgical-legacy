# Magic System v0.1 — the Vis Loop (TL-009)

Status: implemented on `main` (0.1.0-SNAPSHOT). This is the first playable
magic system of Thaumaturgical Legacy and the seed for all later thaumic
milestones (research, aspects, nodes, infusion).

## Goal

A complete, playable loop with no dead ends:

```
craft wand → cast spells (spend vis) → recharge at a Vis Tap → repeat
```

## Scope (what shipped)

| Element | Behavior |
| --- | --- |
| **Thaumic Wand** (`thaumic_wand`) | Right-click casts the active spell. Shift + right-click cycles spells. Right-click on a Vis Tap channels vis from the tap into the wand. Tooltip shows stored vis and active spell. |
| **Firebolt** | 2 vis, 20-block ray, 4.0 magic damage + 4 s ignition, 12-tick cooldown. |
| **Frost Lance** | 3 vis, 24-block ray, 2.0 magic damage + Slowness II for 5 s, 16-tick cooldown. |
| **Vis Tap** (`vis_tap`) | Block + block entity. Gathers 1 ambient vis every 20 ticks into a 100-vis buffer. Right-click with a wand transfers buffer → wand; empty-handed right-click reports the buffer in the action bar. Emits light level 4. |
| **Wand capacity** | 50 vis; a crafted wand starts with 25 so the first cast precedes any infrastructure. |
| **Recipes** | Wand: amethyst shard + stick. Vis Tap: amethyst shard over iron ingot over stick. Vanilla ingredients only. |
| **Creative tab** | Dedicated "Thaumaturgy" tab. |

All numbers are original to this project (docs/REVERSE_ENGINEERING_POLICY.md:
behavior may be *informed* by the documented original, values are ours).

## Architecture decisions

1. **Pure core, thin shell.** `com.jonnyutah12.thaumaturgicallegacy.magic`
   (`Spell`, `SpellDefinition`, `SpellCatalog`, `VisStorage`) contains **no
   Minecraft types**. All numeric rules (costs, cooldowns, transfer/withdrawal
   semantics) live there and are unit-testable without a game bootstrap — this
   matches the TL-010 harness design (JUnit unit tests for pure logic,
   gametests for in-game behavior). Item/block classes only wire the core to
   the game.
2. **State on the stack, not in capabilities.** Wand vis and active spell are
   custom `DataComponentType`s (`vis_stored`, `active_spell`) registered via
   `DeferredRegister.DataComponents`. They persist, sync, and survive
   inventories for free.
3. **Hitscan casting, not projectiles (yet).** The first system raycasts
   (`player.pick`) and draws a particle trail. This avoids entity
   registration/rendering/sync surface while staying playable. A projectile
   entity for longer-range spells is a deliberate later milestone.
4. **One shared vis primitive.** `VisStorage` backs both the wand component
   and the Vis Tap buffer, so transfer rules have exactly one implementation.
5. **Ambient source, not world nodes.** The Vis Tap gathers vis "from
   nowhere" at a slow rate. World vis nodes/auras (the original's model) are
   deferred; the tap keeps the loop closed without worldgen.

## Clean-room compliance

No code, assets, lang strings, or numbers copied from Thaumcraft or Baubles.
Textures are original 16×16 placeholders generated by project tooling
(registered in docs/ASSET_PROVENANCE.md). Names ("Thaumic Wand", "Vis Tap",
"Firebolt") are ours; "vis" is used as a generic English word for the
resource, consistent with the RE policy's nominative-use allowance.
